# 接口错误请求快照设计

最后更新：2026-07-28

## 目标

让超级管理员能够在“接口错误日志”中定位 4xx 与 5xx 请求的入参问题，同时确保密码、令牌、手机号、文件和大体积内容不会写入日志。

## 范围

- 后端所有 HTTP 4xx、5xx 响应写入 `api_error_logs`；接口普通访问日志的开关不影响错误日志。
- 每条错误日志增加 `requestSnapshot` JSON 字段，保存路径参数、查询参数和 JSON 请求体的脱敏快照。
- 仅超级管理员既有的错误日志查询接口返回该字段；管理端详情弹窗展示该快照，CSV 不导出该字段。
- 不记录请求头、Cookie、原始响应体、上传文件、图片/视频、Base64 内容或 multipart 文件内容。

## 脱敏与限长

- 递归脱敏键名：`password`、`token`、`authorization`、`cookie`、`code`、`openid`、`phone`、`idCard`、`bankCard`、`secret` 及其常见变体。
- 手机号保留脱敏形式；敏感字段统一写为 `[REDACTED]`。
- 文件字段、Base64/data URL、Buffer、超长字符串写为 `[OMITTED]` 或截断标记。
- 每个标量字符串最多 500 字符；数组最多 20 项；对象最多 30 个键；整个 JSON 快照最多 8 KiB。
- 无 JSON 请求体时只保存路径和查询参数；请求体解析失败或超限时只记录安全占位信息。

## 管理端行为

- “接口错误日志”默认筛选改为全部错误（4xx + 5xx），状态标签区分客户端错误和服务端错误。
- 详情弹窗增加“请求参数（已脱敏）”区块，格式化 JSON 展示；没有快照的历史记录显示“历史记录未采集请求参数”。
- CSV 导出保持最小化：不导出请求参数，避免离线扩散敏感诊断数据。

## 数据兼容与边界

- 新字段允许为空，历史错误日志保持可读。
- 迁移仅对本地开发库执行；不得修改测试、生产或远程数据库。
- 日志持久化、快照提取或序列化失败不得改变原始业务响应。
