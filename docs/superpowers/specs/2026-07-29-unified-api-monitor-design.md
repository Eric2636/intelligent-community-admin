# 统一接口监控设计

日期：2026-07-29
状态：待用户评审
目标分支：后端与后台管理前端 `dev`

## 1. 目标

将当前“访问记录 / 错误记录”两个页面整合为一个接口监控页面，通过来源 Tab 和状态筛选完成分类，同时优化筛选区域、耗时筛选、真实请求地址、错误详情、分页与导出的一致性。

本次设计只调整接口请求监控，不合并“操作审计”和“小程序异常上报”。“接口日志设置”继续作为独立配置入口。

## 2. 页面结构

接口监控只保留一个菜单和一个页面。

页面顶部仅有两个来源 Tab：

1. 微信小程序
2. 后台管理

不提供“全部”Tab。默认进入“微信小程序”。切换 Tab 时：

- 分别固定查询来源 `MINI` 或 `ADMIN`；
- 重置当前页到第 1 页；
- 保留其他有效筛选条件；
- “用户/管理员 ID”标签分别显示为“用户 ID”和“管理员 ID”；
- 接口下拉只展示当前来源的接口。

原 `/api-error-logs` 页面停止作为独立页面使用，并兼容重定向到统一接口监控页面。

## 3. 状态分类

顶部不再使用“访问记录 / 错误记录”Tab。所有状态在同一列表显示，由状态条件筛选：

- 全部状态；
- `2xx`：成功；
- `3xx`：重定向；
- `4xx`：客户端、登录、权限或参数错误；
- `5xx`：服务端、网关或上游错误。

同时保留精确状态码输入，例如 `200`、`401`、`500`。精确状态码优先于状态类别；选择精确状态码后，状态类别自动清空，避免两个条件冲突。

状态颜色：

- `2xx`：绿色；
- `3xx`：蓝色；
- `4xx`：橙色；
- `5xx`：红色。

## 4. 筛选区设计

筛选区使用 TDesign 风格的浅色面板、明确字段标签、统一控件高度和间距，不再依靠占位文字表达字段含义。

### 4.1 常用筛选

第一行放置：

- IP；
- 接口；
- 请求方法；
- 状态类别；
- 精确状态码；
- 调用时间范围。

第二行放置：

- 用户 ID 或管理员 ID；
- 耗时；
- 查询；
- 重置；
- 导出当前筛选结果。

“来源”下拉框删除，由顶部两个 Tab 替代。

### 4.2 耗时筛选

删除并排的“最小耗时”和“最大耗时”数字框，改成一个“请求耗时”下拉框：

- 全部耗时；
- `100ms` 以内；
- `100ms～500ms`；
- `500ms～1s`；
- `1s` 以上；
- 自定义。

选择“自定义”后，在同一字段区域展开紧凑的范围输入：

```text
[ 最小值 ] — [ 最大值 ] ms
```

约束：

- 最小值、最大值均不得小于 0；
- 两者都有值时，最小值不得大于最大值；
- 输入无效时阻止查询并在当前字段显示中文提示；
- 切换回预设区间时清空自定义值；
- 重置恢复“全部耗时”。

## 5. 统一列表

列表统一按调用时间倒序显示，字段为：

- 调用时间；
- 请求方法；
- 真实请求地址；
- IP；
- 用户或管理员；
- HTTP 状态；
- 业务码；
- 耗时；
- 详情。

不在列表中显示“标准路由”和“脱敏路径”两个重复字段。

真实请求地址要求：

- 包含协议、域名、实际路径和查询参数；
- 动态参数必须是实际 ID，不使用 `:type`、`:id` 等模板；
- 敏感查询参数继续脱敏；
- 单行超长省略，悬浮显示完整内容；
- 地址后提供文本型“复制”按钮，只复制真实请求地址。

详情规则：

- `2xx/3xx`：展示时间、来源、方法、真实地址、操作者、IP、状态、业务码、耗时和请求编号；
- `4xx/5xx`：在上述内容基础上增加错误代码、脱敏错误摘要和脱敏请求参数；
- 不展示 Token、Cookie、Authorization、密码、验证码、上传文件、Base64 或未脱敏手机号；
- 历史记录没有真实地址时明确显示“历史记录未保存真实请求地址”，不拼接或伪造模板地址。

## 6. 数据模型与查询

项目尚未上线，本次采用一张统一请求日志表，避免成功/错误分表造成的跨表分页、排序、筛选和导出不一致。

统一模型至少包含：

- `id`；
- `requestId`；
- `endpointId`；
- `source`；
- `method`；
- `routePattern`；
- `requestUrl`；
- `ip`；
- `userId`；
- `adminId`；
- `httpStatus`；
- `businessCode`；
- `durationMs`；
- `errorCode`；
- `errorSummary`；
- `requestSnapshot`；
- `createdAt`。

其中错误字段和请求快照仅在需要时有值。

迁移策略：

1. 在本地开发数据库创建统一日志表；
2. 将现有访问日志和错误日志复制到统一表；
3. 历史记录缺少完整域名时不伪造 `requestUrl`；
4. 核对迁移前后总数、状态分布和时间范围；
5. 确认后台查询、导出和清理脚本切换完成后，再删除旧表；
6. 删除前创建本地可恢复备份。

生产环境不在本次操作范围内。

## 7. 请求地址可信边界

生产环境完整地址优先从明确配置的公共 API Origin 生成；没有配置时，只有连接来自可信反向代理白名单，才允许读取代理传入的协议和主机信息；其他情况使用 Koa 实际收到的协议和主机。

不得直接信任任意客户端提交的 `Host`、`X-Forwarded-Host` 或 `X-Forwarded-Proto`。

## 8. 查询、分页与导出

后台提供一个统一日志查询接口和一个统一导出接口。

查询支持：

- 来源；
- IP；
- 接口；
- 方法；
- 状态类别；
- 精确状态码；
- 调用时间范围；
- 用户 ID；
- 管理员 ID；
- 预设或自定义耗时范围；
- 请求编号。

分页和导出必须共用同一筛选构造器。导出字段与统一列表保持一致，但不得导出请求快照、错误堆栈或敏感字段。

接口选择器使用服务端搜索和分页，不再只加载前 100 个接口。

## 9. 错误处理

- 日志写入失败不得改变业务接口原始响应；
- 日志写入失败必须输出结构化服务端告警；
- `401`、`403` 等鉴权失败必须记录，即使无法识别操作者；
- 未识别操作者显示为“未认证访问”，不显示成普通业务匿名用户；
- 日志查询失败时保留当前列表，不以旧数据冒充最新结果，并明确提示查询失败；
- 切换 Tab 或重复查询时只接受最后一次请求结果，避免旧请求覆盖新条件。

## 10. 测试与验收

后端至少覆盖：

- `2xx/3xx/4xx/5xx` 写入统一表；
- `401` 无操作者日志；
- 真实地址、实际动态 ID、查询参数脱敏；
- 来源、状态、时间、操作者和耗时筛选；
- 精确状态码与状态类别互斥；
- 统一分页和导出；
- 旧表数据迁移与计数核对；
- 日志失败不影响业务响应；
- 本地清理脚本只清理目标日志。

后台前端至少覆盖：

- 仅显示“微信小程序 / 后台管理”两个 Tab；
- 默认微信小程序；
- Tab 切换与页码重置；
- 状态分类代替访问/错误 Tab；
- 耗时预设、自定义校验和重置；
- 真实地址展示与复制；
- `4xx/5xx` 错误详情；
- 查询失败不继续展示为最新结果；
- Enter 查询、重复查询去重和旧请求淘汰；
- 响应式布局与 TDesign 风格一致性。

最终验收必须执行后端构建、Lint、完整测试，后台前端构建和页面测试，并在本地 `127.0.0.1` 服务与本地开发数据库完成手工验证。
