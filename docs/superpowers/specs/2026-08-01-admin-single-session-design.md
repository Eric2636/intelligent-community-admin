# 后台管理员单账号单会话设计

## 目标

后台管理系统同一管理员账号只保留一个有效会话。新的成功登录立即使该账号此前签发的访问令牌和刷新令牌失效；修改密码、重置密码或停用账号时也立即注销已有会话。

## 范围

- 后端管理员登录、刷新令牌和后台接口鉴权。
- 管理员修改密码、超级管理员重置密码、管理员停用等安全操作。
- 后台前端对会话失效原因的统一提示和退出处理。
- Prisma 数据库结构、迁移、自动化测试和相关认证文档。
- 复用现有操作审计，不新增菜单或在线设备管理页面。

## 数据模型

在 `AdminUser` 增加非空整数 `sessionVersion`，默认值为 `0`。它表示该管理员当前唯一有效的会话版本。

数据库变更由迁移 `20260801190000_add_admin_session_version` 提供，MySQL 实际执行：

```sql
ALTER TABLE `AdminUser`
ADD COLUMN `sessionVersion` INTEGER NOT NULL DEFAULT 0;
```

管理员成功登录时，后端通过数据库原子自增获得新的 `sessionVersion`。访问令牌和刷新令牌都携带该版本。即使两个登录请求并发，只有最后一次自增对应的令牌能继续通过鉴权。

## 登录和鉴权流程

1. 用户名、密码、验证码和登录限制沿用现有逻辑。
2. 登录验证成功后，原子递增 `sessionVersion`，再用新版本签发访问令牌和刷新令牌。
3. `adminAuth` 验证 JWT 签名和令牌类型后，从数据库读取管理员的 `enabled` 与 `sessionVersion`。
4. 管理员不存在或已停用时拒绝访问；令牌版本与数据库不一致时返回 `401`，错误原因固定为 `session_replaced`。
5. 刷新令牌同样校验管理员状态和 `sessionVersion`，不允许旧设备通过刷新接口重新获得访问令牌。

访问令牌和刷新令牌仍保持现有有效期设置。单会话校验只改变令牌是否仍属于当前会话，不延长有效期。

会话被替换时的响应契约固定为：

```json
{
  "statusCode": 401,
  "message": "账号已在其他设备登录，请重新登录",
  "reason": "session_replaced"
}
```

## 主动注销会话

以下操作成功写入数据库时同步递增目标管理员的 `sessionVersion`：

- 管理员修改自己的密码；
- 超级管理员重置其他管理员密码；
- 管理员账号从启用变为停用。

重新启用账号不会自动创建会话，管理员必须重新登录。普通退出登录只清理当前浏览器本地令牌；由于本设计不保存服务端令牌明文，也不增加独立注销接口。

## 前端交互

后台请求收到 `401 + reason=session_replaced` 时：

1. 清除本地访问令牌、刷新令牌和管理员信息；
2. 不再尝试刷新令牌；
3. 仅显示一次“账号已在其他设备登录，请重新登录”；
4. 跳转登录页，并保留现有路由行为。

其他 `401` 继续使用现有刷新和重新登录流程。这样不会把令牌过期、配置错误等情况错误解释为被顶下线。

## 审计

复用现有后台操作审计：

- 成功登录继续记录管理员、IP、时间和登录动作；
- 修改密码、重置密码、停用账号继续记录对应中文动作和接口；
- 不为每个旧令牌的后续请求生成操作审计，避免日志被失效请求淹没；该请求仍由接口访问日志记录为 `401`，并保留 `session_replaced` 业务原因。

## 数据安全与兼容

- 数据库只保存版本号，不保存访问令牌或刷新令牌明文。
- 迁移上线后，所有迁移前签发的管理员令牌因缺少会话版本而失效，需要重新登录一次。
- 小程序用户登录体系不在本次范围内，不受影响。
- 不增加设备指纹、在线设备列表、强制指定设备下线等尚未需要的功能。

## 测试与验收

- 同一管理员连续登录两次，第一次令牌访问后台接口返回 `401/session_replaced`，第二次令牌正常。
- 第一次登录的刷新令牌也无法刷新。
- 两次并发登录后只存在一个有效会话版本。
- 修改密码、重置密码或停用账号后，原访问令牌和刷新令牌立即失效。
- 重新启用账号后必须重新登录。
- 前端仅对 `session_replaced` 显示顶号提示，并避免刷新死循环和重复提示。
- 管理员登录安全限制、验证码、权限、操作审计及小程序鉴权回归测试通过。
