# 数据库运维管理设计

## 目标

在后台管理系统增加仅超级管理员可访问的数据库运维管理功能，用统一配置替代服务器现有每小时备份 cron，并提供安全、只读的数据表结构查看能力。

## 范围与边界

数据库管理包含两个区域：

1. 备份管理；
2. 数据表。

不提供在线恢复、下载备份、删除备份、修改表结构、删除或清空表、浏览业务行数据、执行任意 SQL。管理 API 不持有 Docker Socket 或宿主机 shell 权限。

只有 `SUPERADMIN` 可以看到菜单、进入路由并调用接口。前端隐藏、路由守卫和后端鉴权三层同时执行。

## 备份设置

首次上线继承当前生产规则：自动备份开启、每小时执行、每小时第 5 分钟触发。管理员可以选择：

- 每小时，并选择执行分钟；
- 每 6 小时，并选择执行分钟；
- 每天，并选择执行时间。

不允许填写原始 cron 表达式。设置保存时验证范围并记录操作审计，审计详情包含修改前后配置和真实请求地址。

自动备份和手动备份都写入固定文件 `ic_prod_latest.sql.gz`。执行过程先生成临时文件，完成压缩完整性校验后原子替换正式文件；失败时保留上一份有效备份。进程锁保证同一时间只有一个任务执行，重复触发记录为跳过。

手动备份需要确认，按钮在执行期间禁用。页面展示最近一次成功时间、结果、耗时、文件大小及最近失败原因，不展示数据库密码或服务器目录等敏感配置。

## 备份执行架构

后台 API 只负责保存配置、创建手动任务和查询状态。独立备份执行器轮询到期任务并调用受限备份命令。执行器使用单独容器或受限运行身份，只获得生产数据库只读导出凭据和固定备份目录写权限。

任务状态为 `PENDING`、`RUNNING`、`SUCCESS`、`FAILED` 或 `SKIPPED`。任务记录触发方式、操作管理员、计划时间、开始/结束时间、耗时、文件大小和脱敏错误信息。

新执行器在测试环境完成自动、手动、并发锁、失败保留旧文件验证后，生产发版时才停用现有直接 cron，避免双重调度。原有最新备份文件继续作为首次替换前的有效备份。

## 数据模型

新增两类持久化数据：

- 单例备份设置：启用状态、频率、执行分钟/时间、更新时间和更新管理员；
- 备份任务日志：触发方式、状态、计划与执行时间、耗时、文件大小、错误摘要和管理员。

迁移只新增表和索引，不修改现有业务表。测试和生产均通过正式 Prisma migration 更新结构。

## 数据表只读管理

数据表列表从 `information_schema` 实时读取当前业务数据库，展示：

- 表名；
- 所属业务模块；
- 中文用途说明；
- 估算行数；
- 数据大小和索引大小。

支持按表名、中文说明和模块搜索。表详情展示字段名、中文说明、数据类型、是否可空、默认值、主键和索引信息，不读取或展示表内业务行数据。

表说明由应用内受控映射提供，未知新表显示“未配置说明”，但不允许管理员在此直接修改数据库注释。系统内部表和迁移表明确标记为系统用途。

## 管理页面

页面遵循企业级管理后台规范：页面标题与简短说明、两个清晰区域、紧凑筛选区、结果工具栏、数据区和分页。关键备份状态使用少量统计卡片，任务历史和表结构使用表格，不把所有信息卡片化。

危险或高影响操作使用明确文字与确认；查看、刷新等低风险操作可使用图标，并提供 tooltip 与可访问名称。加载、空结果、筛选无结果和失败重试状态必须区分。

## 日志与审计

- 每次自动和手动备份均写入备份任务日志；
- 修改自动备份设置、触发手动备份写入后台操作审计；
- 调用数据库管理 API 继续由接口监控记录；
- 错误日志只保存脱敏错误摘要，不记录连接字符串、账号或密码。

## 测试与验收

- 非超级管理员无法看到菜单、进入路由或调用 API。
- 频率和时间验证正确，保存后调度按新配置运行。
- 手动与自动任务使用同一互斥锁和同一最新备份文件。
- 备份失败不覆盖上一份有效文件，成功文件通过 gzip 校验。
- 设置变更和手动执行可在操作审计中查到，所有任务在备份历史中可查。
- 数据表和字段信息准确，任何接口均不能修改表结构或读取业务行。
- 新机制启用后旧 cron 被停用且不存在重复备份。
