# 一键发布分支流转设计

## 目标

从共同父级目录运行发布脚本时，自动完成所选项目的暂存、提交、分支合并、远端推送与部署，减少手工切换分支带来的遗漏。

## 固定流转

- 测试发布：`dev` 合并至 `test`，仅从 `test` 部署测试环境。
- 生产发布：`dev` 合并至 `master`，仅从 `master` 部署生产环境。
- 后端、后台管理系统按照发布范围独立处理；只发布其中一个时，不检查或改动另一项目。

## 交互与失败处理

1. 用户选择发布范围后，脚本将所选项目切换到 `dev` 并展示未提交文件。
2. 用户输入 `y` 后，脚本执行 `git add -A`、标准发布提交、推送 `dev`、切换目标分支、非快进合并并推送目标分支。
3. 脚本再次展示将部署的提交并要求输入 `y`，随后构建、部署和健康检查。
4. 任何切换、提交、合并、推送、测试或部署失败都会立即停止；合并冲突由开发者在 `dev` 解决后重新运行。
5. 成功发布后，所选项目自动回到 `dev`。未选择的项目不切换分支、不提交、不推送。
