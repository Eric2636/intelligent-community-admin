## 接口注册

接口以“大写请求方法 + 标准路由”唯一识别，例如 `GET /api/tasks/:taskId`。动态编号必须使用 Router 提供的标准路由，不能把每个实际编号注册为新接口。找不到匹配路由时使用固定的 `UNMATCHED`，不通过正则猜测路径参数。

`api_endpoints` 记录：

| 字段 | 含义 |
| --- | --- |
| `source` | 调用来源，当前为 `MINI` 或 `ADMIN` |
| `method` | 大写 HTTP 方法 |
| `routePattern` | 标准路由 |
| `description` | 超级管理员维护的接口说明 |
| `logEnabled` | 是否记录普通访问日志，新接口默认 `true` |
| `createdAt` / `updatedAt` | 创建和更新时间 |

启动同步只能更新路由来源，不得覆盖管理员维护的 `description` 和 `logEnabled`。

## 普通访问日志

`api_access_logs` 设计记录：

- 接口编号、来源、HTTP 方法、标准路由和脱敏后的实际路径；
- 可信客户端 IP；
- 已认证的小程序用户编号或管理员编号；
- HTTP 状态、可解析的数值业务状态；
- 请求耗时和调用时间。

普通访问日志不得记录完整请求头、Cookie、Authorization、Token、微信授权凭证、请求体或上传文件内容。当前基础中间件只在状态小于 400 且接口普通日志开启时写入普通访问日志；该行为仍须通过完整自动测试和环境验收。

## 4xx/5xx 错误日志

`api_error_logs` 设计记录接口、来源、方法、标准路由、脱敏路径、可信 IP、操作者编号、HTTP 状态、错误代码、脱敏错误摘要、脱敏请求快照、耗时和调用时间。

无论普通日志开关是否关闭，4xx 与 5xx 都必须写入独立错误日志。错误详情仅展示路径参数、查询参数和 JSON 请求体生成的脱敏且限长快照；不得包含完整堆栈、请求头、Cookie、Token、密码、微信凭证、文件、图片/视频、Base64 内容或未脱敏手机号。CSV 不导出请求快照。日志写入失败时，原接口状态码和响应体必须保持不变，同时服务器应输出明确的日志持久化故障告警。

## 脱敏

敏感键至少包括：

- `password`
- `token`
- `authorization`
- `cookie`
- `code`
- `phoneCode`
- `refreshToken`

手机号只允许保留必要的掩码形式。CSV、后台详情和服务端故障告警必须复用同一安全边界，不能因为展示或导出而绕过脱敏。不得持久化上传文件内容。

## 可信代理与客户端 IP

默认不信任客户端提供的转发头，使用连接的 socket IP。只有服务部署在明确受控的反向代理后，才允许设置：

```dotenv
TRUST_PROXY=true
TRUST_PROXY_IPS=127.0.0.1,::1
```

启用前必须确认代理会覆盖外部传入的 `X-Forwarded-For`，并在测试环境验证客户端不能通过伪造该请求头篡改日志 IP。代码仅在 `TRUST_PROXY=true` 且连接 socket peer 精确命中 `TRUST_PROXY_IPS` 逗号分隔白名单时读取转发链首项；未配置或未命中可信 peer 时始终使用 socket IP。`.env.example` 已给出示例，目标环境仍需配置实际代理白名单并完成代理链验收。

## 权限、筛选和导出（已有实现，待验收）

以下能力只允许超级管理员使用，普通管理员必须同时被后台菜单/路由和后端 API 拒绝：

- 查看接口列表；
- 修改接口描述和普通日志开关；
- 查询普通访问日志和 4xx/5xx 错误日志；
- 导出当前筛选结果。

访问日志接口已实现按 IP、接口、方法、来源、精确状态码或状态类别、调用时间范围、用户/管理员编号和耗时筛选，默认按调用时间倒序分页；仍须通过完整自动测试和环境验收。

状态类别当前统一支持 `2xx`、`4xx`、`5xx`。后台选择项、后端筛选器和 OpenAPI 已一致，不再提供无后端语义的 `3xx` 选项。

接口描述与日志开关变更分别写入 `API_ENDPOINT_DESCRIPTION_UPDATE` 和 `API_ENDPOINT_LOGGING_UPDATE`。同一 PATCH 同时包含 `description` 和 `logEnabled` 时会分别记录两类实际变化，未变化的字段不重复记日志；`test/api-log.routes.spec.ts` 已覆盖该行为。

CSV 导出必须与列表共用同一筛选构造器，最多 50,000 行，使用 UTF-8 BOM。允许导出的字段仅限时间、来源、方法、标准路由、脱敏路径、IP、操作者编号、状态和耗时。BigInt 日志编号在 JSON 或 CSV 边界必须转换为十进制字符串。

## 90 天保留（脚本已实现，待演练和接入）

普通访问日志和 4xx/5xx 错误日志保留 90 天。清理任务应：

- 只删除 `createdAt < 当前时间 - 90 天` 的记录；
- 访问日志和错误日志分别分批处理；当前脚本每批 5,000 行，满足每批最多 5,000 行的限制；
- 每批单独提交，避免长事务；
- 不删除接口配置和管理员操作日志；
- 输出删除数量、耗时和失败状态，供运维记录。

当前 `test/api-log-retention.spec.ts` 已覆盖 90 天截止时间、边界保留、5,000 行批次上限及访问/错误日志分别清理。专用测试数据库仍须插入 89、90、91 天样本演练真实数据库边界。仓库已有 `npm run cleanup-api-logs` 脚本和 `docs/api-log-retention-cron.md` 部署示例，但尚未证明目标环境定时任务已接入，不能把保留策略写成已经生效。
